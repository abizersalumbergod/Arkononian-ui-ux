# Pilot build: Fieldnote waitlist page (2026-10-29)

A real build that follows `SKILL.md` stages 1 to 11, used to check that the skill works end to end and not only in plans. Fieldnote is a fictional offline-first note-taking app for field researchers.

**Request:** a high-converting waitlist landing page with a strong hero, social proof and one call to action (an email form with validation and a success state). Plain HTML, CSS and vanilla JS in one folder, no framework, no npm installs, procedural or SVG visuals only, no paid generation.

**Model:** claude-opus-5-5. **Skill state:** the working tree after the fixes listed under CHANGELOG "Unreleased".

## What the pilot taught about the skill

- **Fixed now:** pre-launch field data is NOT_TESTED, as the workflows already said; `quality-gates` rule 5 now says so too.
- The lower secondary threshold adds `asset-production` here, which also loads the video and audio modules a page with only SVG visuals does not need. Module loading per media modifier is the next router change.
- `visual-check.mjs --axe` needs `axe-core`, which was not installed; the Lighthouse fallback in the gate table worked.
- The Lighthouse tool used here excludes performance, so the lab interaction measure (TBT or INP) needs a scripted interaction inside a trace.
- Playwright's `javaScriptEnabled: false` stops scripts but does not render `<noscript>` content, so a no-JS notice can only be checked for presence.

The page, its checks and their artifacts stayed in the session scratchpad; this file and the quality report numbers above are the record. Placeholder copy and proof (marked `TODO(content)` on the page) are listed in that report.
