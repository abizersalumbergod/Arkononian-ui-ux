# Skill and capability audit

An audit of the UI/UX skills, plugins, tools and documentation available when this skill was built. It records what each source contributes, how it was used (incorporated, adapted, referenced at runtime, or rejected), under which licence, where sources conflict, and which gaps this package had to fill.

**Load when:** maintaining or extending this skill, resolving a conflict between installed skills, or checking where a rule came from. **Owns:** source comparison matrix, provenance ledger, conflicts and precedence decisions, gap analysis.
**Related:** [skill-delegation](skill-delegation.md), [capability-registry](capability-registry.md), [quality-gates](quality-gates.md), [../LICENSES_AND_PROVENANCE.md](../LICENSES_AND_PROVENANCE.md)

## Decision rules

1. Treat this audit as a dated snapshot (2026-10-23/24). Re-run the audit when skills are added, removed or updated.
2. Sources with no licence found contribute ideas only, paraphrased. Prefer invoking the installed skill at runtime over embedding its text.
3. MIT and Apache sources may be adapted, with attribution in `LICENSES_AND_PROVENANCE.md`.
4. Resolve conflicting advice with the precedence order in SKILL.md §2. Specialist-skill heuristics rank below accessibility, product goals, performance and brand.
5. A rejected technique stays rejected until new evidence (a standard, measured data, or a maintained source) supersedes the reason recorded here.
6. Close every gap in the gap analysis with a module, script or test, never with a promise. The acceptance-test column names the proof.

## Scope and method

- **Inspected:** 10 skill groups and 5 research topics. Raw audit data was produced by auditor agents that read each SKILL.md and its supporting files, then condensed into per-module briefs.
- **Environment:** Windows 11 Home 10.0.26200; shells: PowerShell 5.1 and Git Bash. Runtimes and MCP verification are in [capability-registry](capability-registry.md).
- **Not on disk (built-ins loadable only through the Skill tool):** dataviz, artifact-design, artifact-diagramming, artifact-capabilities. The dataviz method was read through the Skill tool by the dashboard researcher.
- **Inaccessible or limited during the audit:** Supabase MCP disconnected; desktop-commander failed to connect; Context7 MCP not configured; GitHub and Figma plugin MCPs need OAuth. Higgsfield generation was never invoked: the account has 0 credits and generation needs approval.
- **Interruptions:** several agent runs stopped at the account usage limit. Completed outputs were kept and only the gaps were re-run.
- **Partial coverage:** (1) the "own style skills + ECHO source" group catalogued its sources, but the techniques live in the two style skills' `recipes.md` files, which the 3D and motion module writers read directly; (2) the asset-tool catalogue agent did not finish, so generator facts come from direct read-only probes (balance, model listing) recorded in the capability registry; (3) unresolved research questions are listed under "Research findings".

## Conflicts and precedence decisions

Conflicts reported by the auditors (up to six per group, de-duplicated). Each one is resolved by the SKILL.md §2 precedence order unless a resolution is stated.

### Anti-slop taste: design-taste-frontend

- Em-dash and en-dash total ban (9.G) conflicts with standard typography (en-dash for ranges) and some locales. Adopt as a default for UI microcopy plus a reported lint metric, not a hard fail
- 'MUST use image generation if available' (4.8) conflicts with this environment's rule that paid or credit generation (Higgsfield 0 credits, Figma generate_image cost unknown) needs explicit user approval
- Real third-party logos for 'Trusted by' walls (4.8) conflicts with honesty and trademark norms unless the customers are real; also conflicts with the Artifact rule against content that imitates real organisations
- Never using Google Fonts <link> (3.A) conflicts with the claude.ai Artifact page contract, where Google Fonts is the only allowed external stylesheet source
- Mandatory dark mode for consumer pages (6.C, 8) conflicts with single-theme style presets such as cinematic-noir-studio; make it a default with a preset override
- 'transition: all 0.3s' in MOTION 4-7 (7) conflicts with the source's own transform/opacity-only rule (6.A) and with emil-design-eng and transitions-dev, which say to name properties

- Live regions: frontend-a11y pairs role=status with aria-live=assertive and uses role=alert on every field error; common guidance is one polite status region and focus/summary on submit.

- Modal focus trapping: ECC accessibility cites SC 2.1.2 as requiring containment; 2.1.2 prohibits inescapable traps. Containment is the APG dialog pattern (native <dialog> provides it).

- Playwright waits/locators: e2e-testing uses networkidle and data-testid; Playwright guidance prefers web-first assertions and role/label locators and discourages networkidle.

### Media, video, 3D asset & generative pipelines

- video-editing's Remotion example imports Video from 'remotion' and uses absolute '/segments/...' paths, while remotion-video-creation requires Video/Audio from @remotion/media and staticFile() for public assets. Resolution: detect the installed Remotion version, then follow remotion-video-creation.
- remotion-video-creation/videos.md says trimBefore/trimAfter are in seconds, but its example and audio.md use frames (2 * fps). Resolution: values are frames; flag the doc error.
- remotion-video-creation bans CSS transitions/animations entirely, while web UI motion guidance (motion-engineering, transitions-dev, emil-design-eng) prefers CSS transitions for live UI. Resolution: the ban applies only to frame-rendered output and deterministic captures.
- Remotion's 'bouncy' preset (damping 8) for entrances vs product-UI guidance that avoids overshoot on functional elements. Resolution: bounce only for playful/marketing video moments, never for UI state feedback.
- fal-ai-media activates on any media generation request and calls generate() directly, while BUILD-SPEC and tasteforge-video require explicit approval and fail-closed generation. Resolution: approval gate always wins (precedence rule 1).
- Loudness: video-editing uses -16 LUFS integrated; broadcast standards use -23 LUFS (EBU R128) / -24 LKFS (ATSC A/85), and many streaming platforms normalise around -14 LUFS. Resolution: choose the target by delivery destination; default -16 for web.

**Standing resolutions:** (1) accessibility and functional correctness beat taste rules, for example "no hover-only reveals" beats glass-card blur reveals; (2) the product's task density beats house style, so dashboards stay dense and neutral even when a taste skill prefers editorial whitespace; (3) one motion library per project unless a measured need exists; (4) generated assets need approval when they cost credits, whatever a media skill suggests; (5) style catalogues and presets are starting points, never mandates.
